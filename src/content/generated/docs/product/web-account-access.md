# 章節目標
理解登入、註冊合併，訪客帳號建立、登入與升級正式帳號的主要驗證路徑。
## 身分路徑
2026 流程將登入與註冊收斂到同一入口，並加入訪客帳號建立與 claim 成為正式帳號。測試時先確認使用者目前身分，再驗證系統是否帶往正確路徑。

## 失敗與恢復
- 驗證碼錯誤、過期、重送與頻率限制都有明確提示。
- 關閉、返回或重新整理不會跳過必要驗證，也不會重複建立身分。
- 第三方登入、Passkey 或裝置能力不可用時，仍提供可理解的替代方式。
- claim 失敗時保留訪客權益，並提供重試或聯絡客服的出口。
<callout icon="⚠️" color="yellow_bg">
	帳號合併與訪客升級會改變使用者身分；需保留失敗前後的識別、權益與訂單證據，但公開 issue 不得包含真實個資或驗證資訊。
</callout>
