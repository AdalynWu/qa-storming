# 聊天功能導覽
聊天體驗包含房間列表、未讀狀態、訊息歷史、送出流程與各種訊息類型。驗證重點是順序、狀態同步與中斷後是否能安全恢復。
## 聊天室主頁
- 房間列表應依產品規則排序，最新訊息摘要、時間與未讀數需彼此一致。
- 新房間、空列表、載入中、載入失敗與重新整理要有清楚狀態。
- 收到新訊息後，列表摘要、未讀徽章與系統通知應在合理時間更新。
- 切換帳號或重新登入後，不可顯示上一個帳號的房間與未讀資料。
## 單一聊天室
1. 進入房間後確認對話對象、歷史訊息與日期分隔正確。
2. 送出文字訊息，檢查傳送中、成功與失敗狀態。
3. 失敗後執行重試，確認不重複訊息且時間順序正確。
4. 收到新訊息時，畫面應合理定位，不強制打斷正在閱讀較舊內容的使用者。
5. 返回列表後，最後訊息與未讀狀態應同步。
## 訊息類型與輸入
- 空白、超長文字、換行、表情符號與組合字元需符合輸入限制。
- 圖片、連結與系統訊息應有可辨識樣式；失效內容需有替代呈現。
- 鍵盤開合、貼上內容、切到背景及旋轉螢幕後，輸入內容不應無故遺失。
- 上傳媒體時需驗證權限、取消、失敗、重試與進度狀態。
## 安全與權限
- 被封鎖、房間失效或權限不足時，使用者應收到明確且不洩漏額外資訊的提示。
- 檢舉或安全入口若存在，完成與取消流程都需能回到正確位置。
- 通知預覽與鎖定畫面內容應符合產品隱私設定。
- 深層連結進入不存在或無權限的房間時，不應卡在空白頁。
## 網路與同步
<callout icon="⚠️" color="yellow_bg">
	優先測試離線送出、弱網路、重複點擊、App 背景恢復與多裝置同時收到訊息；這些情境最容易造成重複、亂序或未讀數不一致。
